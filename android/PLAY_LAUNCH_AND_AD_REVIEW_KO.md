# 모두의 보드점수+ · 스토어 심사 및 수익화 차단요인 체크 (2026-10)

## 현재 직접 확인한 사항
- 앱 ID: `io.github.workto0725.boardscoreplus`
- Android targetSdk/compileSdk: 36
- 광고용 SDK: Google Mobile Ads 25.5.0, UMP 4.0.0
- Debug APK에서는 Google 공식 테스트 배너만 이용. 실제 수익 없음.
- Release에서는 광고 UI를 생성하지 않도록 설정되어 있지만, SDK 자체 의존성은 포함됨.
- GitHub Actions에 디버그 APK 및 별도의 서명된 업로드 AAB 워크플로가 있음.
- 개발자 서명 키 등록과 실행 결과는 확인되지 않음.
- 웹 공개 개인정보 안내 페이지 `https://workto0725.github.io/boardscore/privacy.html`은 **초안**임.

## 실제 Play 심사 제출 전에 완료할 필수 확인
1. **운영자 연락처**: 개인정보 처리방침에 게시할 실제 문의 이메일 결정.
2. **서버 데이터 삭제 절차**: 공동 게임방 기록, Storage 사진, 오래된 파일의 보관 기간·삭제 처리 정책을 확정하고 실제로 구현·검증.
3. **데이터 보안 폼**: Supabase로 전송되는 방 정보·별명·사진, 로컬 점수 저장, 광고 SDK가 전송할 수 있는 데이터 등을 실사용 및 SDK 문서 기준으로 신고.
4. **광고 여부**: 정식 출시 시 실제 광고를 넣는 경우 Play Console의 광고 포함 항목 및 UMP 개인정보 안내를 업데이트. 현재 테스트 ID를 실제 ID로 바꾸기만 하는 것은 충분하지 않음.
5. **미성년자 대상 설정**: 대상 연령과 가족 정책 적용 범위 확인. 어린이를 대상으로 하는 경우 별도의 SDK·광고 제한 검토 필요.
6. **콘텐츠 평가 및 스토어 설명**: 게임/앱 분류, 콘텐츠 등급, 개인정보 방침 URL, 스크린샷, 지원 정보 등록.
7. **앱 번들**: 본인 소유 업로드 키로 서명된 AAB 빌드 성공과 실제 갤럭시 테스트.
8. **검증**: 브라우저와 Android WebView에서 QR 연결, 서버 동기화, 이미지 업로드/저장, 화면 복원, 오류 시 네트워크 안내 테스트.

## 수익화 로드맵
- 1단계: 사용자 방해 없는 테스트 배너와 동의 UI 실기기 점검
- 2단계: 운영자 명의 AdMob 앱/광고 단위 생성, 실제 앱 ID 안전한 빌드 구성으로 연결
- 3단계: 개인정보 방침/삭제 절차 완비 후 광고 켜기
- 4단계: 광고 제거 구매 기능 도입(구매 검증 및 Google Play Billing 포함)

**주의:** 이 파일을 GitHub에 추가했다는 사실만으로 Play Console의 설정·서명·업로드가 완료된 것은 아닙니다.
